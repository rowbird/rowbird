# ADR-0017: Authorization declared in the OpenAPI document

- **Status:** Accepted
- **Date:** 2026-09-25

## Context

Authorization must deny by default and every operation must declare its required role and API key
scope (docs/spec/07-security.md). The rule could live in each handler, in a Go table, or in the API
contract. Rules in handlers are easy to forget; a Go table drifts from the contract that clients and
docs read.

## Decision

Each operation in `api/openapi.yaml` carries `x-rowbird-authz` with `role`, `scope` and the optional
flags `session_only` and `allow_restricted`. Public operations use `security: []` and carry no rule.

- At startup the server reads the embedded document (generated by oapi-codegen) and builds the
  policy table. An operation that is neither public nor declares a valid rule makes the router
  refuse to start.
- A strict-server middleware, which receives the operation id, enforces the table before the handler
  runs, then binds the caller's workspace to the context for the store.
- A test of the contract requires the extension on every non-public operation and a fixed list of
  public ones. A separate permission matrix test, written by hand, calls every operation as every
  kind of caller and compares the outcome with its own table, so changing either the contract or
  the test alone fails.

## Consequences

The rule of an endpoint is visible in the contract, in generated docs and in code review of the YAML.
Adding an endpoint forces an explicit decision. Rules that depend on the resource itself (for
example, the last admin) remain in the services.
