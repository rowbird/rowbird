# 06: UI

## Global

- Left sidebar, grouped by task: Home; **Build** (Queries, Reports); **Follow** (Runs, Links);
  **Set up** (Connections, Channels); Settings at the bottom with the new-version notice. It
  collapses to icons, and starts collapsed on the query and report editors, which need the width;
  the expanded or collapsed choice is remembered in the browser separately for editors and for
  other pages.
- Pages start at the same left edge as the top bar. Lists and details use the full width; forms
  (connection, channel, report editor, profile) cap their width but are never centered.
- Top bar: a search field that opens the **Ctrl/⌘+K** command palette (pages and settings
  sections, create actions for the caller's role, and reports, queries, connections and channels
  by name, ignoring accents; arrows and Enter), notifications
  bell (with the unread count; it opens the notification center in a side sheet: newest first,
  the number of occurrences of grouped ones, the error, resolved state, mark one or all as read,
  a click leads to the channel or report), theme toggle, user menu.
- **Health banner** on every page while a channel is failing or a report is failing or paused after
  failures, naming it when there is one and linking to it (or to the list).
- Data refreshes from server-sent events; while something is unfinished, views also poll every 15
  seconds (every 2 while the event stream is down).
- Responsive: checking runs, resending deliveries and reading notifications MUST work on phones.
- Light/dark themes; all strings i18n (`en`, `pt-BR`).

## Screens

**Setup wizard**: admin account, language, timezone, setup token when required, master key warning
that must be acknowledged before continuing.

**Forced account steps**: a session with a temporary password only sees the change-password screen;
when the workspace requires 2FA, a user without it only sees the enrollment screen, which offers a
passkey (when available) or an authenticator app. Both offer sign out.

**Login**: email/password; the second step offers the methods the account has (a passkey button, a
TOTP code, a recovery code); "Sign in with a passkey" when passkeys are available (the server knows
its public URL and the browser supports them); the OIDC button (its label from the settings) when
single sign-on is on, and the provider's errors translated from `oidc_error`; forgot password
(shown only with a system mailer channel and `ROWBIRD_BASE_URL`: it asks for the email and always
answers the same; the emailed link opens a page to choose the new password, then sign in). Closing
the browser's passkey prompt is not shown as an error.

**Home**: next runs, recent failed and partial runs, success rate of the last 7 and 30 days (with
the counts behind it), failing channels with their last error, quick actions for editors (new
report, new query); each card has an empty state. For editors and admins, until it is done or
hidden (remembered in the browser), the **first-use checklist**: connect a database (admins; editors
are told to ask one), write a query, schedule a report, receive the first delivery. Done steps are
checked from the workspace's data (`onboarding` in `GET /dashboard`), and only the next step has a
button. This flow is what the README GIF shows.

**Connections**: list with status and write-permission warning; schema-driven form + SSH tunnel;
test button; **schema browser** (tables/columns/types, search); AI table exclusion.

**Queries** (most important screen)
- List: connection, author, last change, number of reports using it.
- Editor: title with an editable slug (derived from the title until the user edits it), connection
  picker, schema panel (click inserts name) | SQL editor (CodeMirror with the connection's dialect,
  autocomplete from the schema, `{{param}}` highlighting, Ctrl/⌘+Enter runs the preview) |
  parameters panel (detects parameters as you type, type and default for each, flags unused
  definitions) | results panel (rows, columns with types, duration, truncation, resolved params and
  the time zone used; numbers and dates formatted with the user's locale, decimals kept exact).
- Save asks for an optional version note.
- AI panel (**Ctrl/⌘+I**, or the Assistant button): prompt (Ctrl/⌘+Enter proposes) → proposal with
  explanation, warnings, suggested name, new parameters and a diff against the current SQL → Apply
  (replaces the SQL, adds the parameters, fills an empty title) or Discard. Nothing runs by itself.
  When the assistant is off the panel says so and links admins to Settings > AI.
- Versions drawer: list, diff between versions, restore.
- Save shows impact when used by reports.

**Reports**
- List: status (active/paused/failing), next run, last result, enable toggle.
- Editor, single page with sections: Query (with values for the query's parameters) · Schedule
  (builder + cron + timezone + next 5 runs, in the report's time zone and the user's; with the AI
  assistant on, "describe when to run" proposes cron and time zone with the next runs, applied only
  on request) · Conditions
  (rules rendered from each condition plugin's schema) · Advanced (row limit, retries, backoff,
  misfire, overlap, auto-pause, owner notification). Deliveries are managed on the report page, since
  they belong to a saved report.
- Detail: summary (query, schedule description, next run, condition), actions (run now, run and
  deliver, pause/resume, edit, delete), a chart of the latest 30 runs (bars by duration, colored by
  outcome, each opening its run; success rate over finished runs, median duration, last failure),
  recent runs; the page refreshes while a run is active.
- Deliveries as cards (channel, mode, formats, disabled state) in order; an empty state explains
  deliveries and links to creating a channel when there is none. The delivery editor offers only
  the channel's modes, file formats for file modes, inline rows, link expiry and login requirement,
  and the destination's options rendered from its `delivery_schema`; it shows a **live message
  preview** (HTML in a sandboxed frame with no permissions, text as is) and field errors next to the
  fields. The link mode explains when `ROWBIRD_BASE_URL` is missing (`settings.links_enabled`).
  Removing a delivery is confirmed.
- "Send test to me" always visible (by email through the system mailer), plus "test on this
  channel" for each delivery's channel.
- Detail: run timeline, charts of duration and row count over time, deliveries, recent errors.

**Channels**: list with type, health, last activity and how many reports use each, plus an empty
state; schema-driven form (the type cannot change after creation, secrets show "configured") with a
test of the unsaved settings and the system mailer switch for email channels; detail with health
(last success, last failure, error), capabilities (modes, attachment limit), test send, "used by"
list, **resend all failed** for the last 24 hours, and a delete that is blocked while deliveries use
the channel. Only admins create, edit and delete; editors test and resend. System alert flags
arrive in roadmap phase 7.

**Runs**: global list with filters (status, report, period, trigger) kept in the URL, "load more"
paging. Run detail as steps: Query → Condition → Formats → Deliveries, each with status, duration,
error; exact SQL version + resolved params; the result sample (first 100 rows); downloads of the
result in every file format for 24 hours; the files the deliveries generated (size, until when they
can be downloaded); each delivery attempt with channel (or "deleted channel"), status, tries, error
code and message, attachments and links, the link fallback note and a **resend** button for failed
ones; cancel. Lists and details refresh when their runs change (server-sent events).

**Links**: shared links newest first with file, report and run, status (active, expired, revoked
and by whom), expiry, login requirement, download count and last download, an "active only" filter,
"load more" paging and a confirmed revoke. The file name opens a side panel with the link's details
and its latest 100 downloads: when, who (the signed-in user's name, or anonymous), IP and a short
"browser on OS". Opening a link that requires a login sends the visitor to the login page and back
to the download.

**Import / Export**: export from the report list (checkboxes; none selected exports all) or the report
page, with the connections and channels optionally included, as a YAML download. Settings > Import /
export (admin): upload or paste → check (a dry run) → errors with their lines · map missing
connections/channels · fill secrets (required for new resources, optional to keep stored ones) ·
decide conflicts per item (overwrite/copy/skip) with the field diff → apply, enabled only when
nothing blocks. Every change re-checks. Resources managed by the configuration directory show a
notice, hide their edit and delete actions, and offer admins "Edit anyway" (detach); detached ones
offer "Give back to the directory". Orphan reports show a badge and an explanation.

**Settings**: General (locale, timezone) · Alerts (admin: primary and fallback channel, each with
its destination's options except message templates, a warning when both have the same type; the
heartbeat URL, shown only as "a URL is saved" with replace and remove, and its interval) · AI
(admin: provider or off, the provider's settings from its schema with the key shown only as
configured, a test, and a note on what is sent) · Storage & retention (admin: runs and file
retention in days, the fixed periods, space used, when the cleanup last ran, the scheduled backup
status or how to turn it on, and a reminder that backups do not include the master key) · Users &
roles · API keys · Security (require 2FA; single sign-on: the redirect URI to copy, issuer with a
test, client id, client secret shown only as saved, scopes, button label, allowed domains,
auto-provisioning and its role) · About (visible to everyone: version, commit, build; the update
check toggle for admins, disabled when the server turned it off; the new release with a link to
its notes). Admins see "Version X is available" at the bottom of the sidebar.

**Profile**: name, password, 2FA, passkeys (name, when added and last used, synced; add with a name
and the current password, rename, remove with the current password), sessions (revoke, sign out
everywhere), language, theme.
Language and theme are stored in the profile; before sign-in they come from the browser.

**Settings > Users & roles**: visible to everyone, read-only for non-admins. Adding a user shows the
temporary password once. Role changes, disabling, password resets and turning off another user's 2FA
are confirmed with their impact. **Settings > API keys** and **Settings > Security** (require 2FA,
security events with a type filter) are admin only.

## UX principles

- Empty states explain the concept and offer the create action.
- Preview before acting (query, cron, message, import).
- Destructive actions confirm and show impact.
- Errors show the human message plus the stable error code (copyable).
- Keyboard-friendly; accessible (labels, focus states, contrast). The E2E runs axe on the main pages
  and allows no serious or critical violation; scrollable tables can take the keyboard focus.
- Works on phones: at 375px no page scrolls sideways (checked in E2E); wide tables scroll inside
  their card. Filtered lists that come out empty say so and offer to clear the filters.

## Form fields

- A field's hint stays visible when it has an error; the error shows below it.
- Message template fields (options whose help is `plugin.template.help`) list the template
  variables as buttons under the field; a click inserts `{{name}}` at the cursor.
- The email channel form warns when port 465 is used with `starttls` or port 587 with `tls`,
  since such a test only ends at its timeout.
